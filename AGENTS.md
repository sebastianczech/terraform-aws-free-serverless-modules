# Instructions for Claude Code

This document provides guidance for Claude agents working on the terraform-aws-free-serverless-modules project.

## Project Overview

**Purpose:** A collection of reusable Terraform modules for provisioning free-tier serverless resources in AWS cloud.

**License:** MIT License

**Key Philosophy:** All modules are optimized for AWS free tier limits with security-first approach and minimal manual intervention through automation.

## Available Modules

### Lambda Module (`modules/lambda/`)
Creates Lambda functions with:
- Configurable runtime (default: Python 3.12)
- Lambda function URL with AWS_IAM authorization
- IAM role and policies
- CloudWatch log group (1-day retention for free tier)
- Optional integrations: SQS event source mapping, SNS publishing, DynamoDB access
- Lambda permission for IAM user invocation
- Built-in health check via Terraform `check` blocks

### DynamoDB Module (`modules/dynamodb/`)
Creates DynamoDB tables with:
- Default capacity: 1 RCU/WCU (free tier)
- Hash key with type validation (S, N, or B)
- Server-side encryption enabled

### SQS Module (`modules/sqs/`)
Creates SQS queues with minimal configuration for simplicity.

### SNS Module (`modules/sns/`)
Creates SNS topics with subscriptions and protocol validation (email, sms, lambda, sqs, application).

## Critical Development Guidelines

### 1. Testing Approach (IMPORTANT)

**This project does NOT use traditional unit or integration tests.**

Testing is performed through:

1. **Pre-commit hooks** (`.pre-commit-config.yaml`):
   - terraform_fmt: Format code
   - terraform_validate: Validate configuration
   - terraform_docs: Auto-generate documentation
   - terraform_tflint: Lint with AWS best practices
   - terraform_providers_lock: Lock providers for linux_arm64, linux_amd64, darwin_amd64
   - checkov: Security policy scanning
   - trivy: Infrastructure security scanning
   - gitleaks: Secret detection

2. **CI/CD workflows** (`.github/workflows/pre-commit.yml`):
   - Tests with MINIMUM supported Terraform version (1.5.0)
   - Tests with MAXIMUM supported Terraform version
   - Super-linter validation

3. **Terraform check blocks** (Lambda module):
   - Runtime health checks by curling function URLs

**When making changes:**
- Run `pre-commit run -a` before committing
- Ensure all hooks pass
- CI will test with multiple Terraform versions

### 2. Documentation (AUTO-GENERATED)

**NEVER manually edit README sections between:**
```markdown
<!-- BEGIN_TF_DOCS -->
...
<!-- END_TF_DOCS -->
```

Documentation is auto-generated by terraform-docs (v0.19.0).

**To update documentation:**
1. Modify variables, outputs, or resources
2. Run `pre-commit run terraform_docs -a` or commit (hook will update automatically)

**Requirements:**
- All variables MUST have `description` (enforced by tflint)
- All outputs MUST have `description` (enforced by tflint)
- Include inline comments with official documentation URLs

### 3. Version Management

**Terraform Versions:**
- Minimum: >= 1.5.0 (defined in all `versions.tf`)
- CI tests with both min and max versions

**Provider Versions:**
- AWS: ~> 5.71 (consistent across all modules)
- External: ~> 2.0 (lambda module only)
- Archive: ~> 2.0 (examples)

**Provider Locking:**
- MUST lock for three platforms: linux_arm64, linux_amd64, darwin_amd64
- Use `terraform providers lock` or pre-commit hook
- Never commit without locked providers

### 4. Semantic Versioning and Commits

**Commit Message Format (STRICT):**
```
<type>(<scope>): <description>

[optional body]

[optional footer]
```

**Types and Version Impact:**
- `breaking`: Major version (1.0.0 -> 2.0.0)
- `feat`: Minor version (1.0.0 -> 1.1.0)
- `fix`, `perf`, `revert`: Patch version (1.0.0 -> 1.0.1)
- `docs`, `style`, `refactor`, `test`, `chore`, `ci`: Patch version

**Examples from project history:**
```
chore(deps): bump hashicorp/aws from 5.94.1 to 5.99.1 in /modules/sqs (#148)
chore(release): version 1.5.10 [skip ci]
```

**Release Process:**
- Automated via `.github/workflows/release.yml` (manual trigger)
- Uses semantic-release to generate CHANGELOG.md and GitHub releases
- Add `[skip ci]` to commit message for release commits

### 5. Coding Standards

**File Structure (every module):**
```
module/
├── main.tf          # Primary resource definitions
├── variables.tf     # Input variables
├── outputs.tf       # Output values
├── versions.tf      # Terraform and provider constraints
└── README.md        # Auto-generated documentation
```

**Resource Naming:**
- Primary resource: `this` (e.g., `aws_lambda_function.this`)
- Supporting resources: prefix with purpose (e.g., `lambda_logging`, `lambda_sqs`)
- Conditional resources: use `count` with ternary operators

**Variable Conventions:**
- All variables MUST have descriptions
- Use `optional()` for complex object types with defaults
- Add `validation` blocks for constrained values
- Set defaults to free-tier optimizations (capacity = 1, retention = 1 day)

**Example variable pattern:**
```hcl
variable "hash_key_type" {
  type        = string
  description = "DynamoDB table hash key attribute type"
  default     = "S"

  validation {
    condition     = contains(["S", "N", "B"], var.hash_key_type)
    error_message = "hash_key_type must be S, N, or B"
  }
}
```

### 6. Security Standards

**Required Security Scanning:**
- Checkov: Policy-as-code scanning
- Trivy: Infrastructure vulnerability scanning
- Gitleaks: Secret detection

**Skipped Security Checks:**
- Documented in `.checkov.yaml` and `.trivyignore`
- Only skip checks that conflict with free-tier optimization or are false positives
- NEVER skip legitimate security issues

**Security Features to Include:**
- Enable encryption at rest
- Use AWS_IAM authorization for endpoints
- Follow principle of least privilege for IAM policies
- Enable CloudWatch logging

### 7. Common Development Tasks

**Adding a New Module:**
1. Create directory under `modules/`
2. Create standard files: `main.tf`, `variables.tf`, `outputs.tf`, `versions.tf`, `README.md`
3. Set Terraform version: `>= 1.5.0`
4. Set AWS provider version: `~> 5.71`
5. Add descriptions to all variables and outputs
6. Run `pre-commit run -a` to generate docs and validate
7. Add module to `examples/basic/` if appropriate
8. Update Dependabot config to monitor new module

**Updating a Module:**
1. Read existing module code first
2. Make changes to `.tf` files
3. Update variables/outputs if needed
4. Run `pre-commit run -a` to validate and update docs
5. Test with example: `task example-deploy` (see taskfile.yml)
6. Commit with conventional commit message

**Running Examples:**
```bash
# Deploy example infrastructure
task example-deploy

# Test deployed Lambda functions
task example-check

# Destroy example infrastructure
task example-destroy
```

**Manual Pre-commit Checks:**
```bash
# Run all hooks

# Run specific hook
pre-commit run terraform_fmt -a
pre-commit run terraform_validate -a
pre-commit run terraform_docs -a
```

### 8. Module Integration Pattern

The Lambda module demonstrates integration patterns:

```hcl
# Optional SQS integration with conditional resources
variable "sqs" {
  type = object({
    enabled        = optional(bool, false)
    trigger_lambda = optional(bool, false)
    arn           = optional(string, "")
    url           = optional(string, "")
  })
  default = {}
}

# Conditional IAM policy
resource "aws_iam_policy" "lambda_sqs" {
  count = var.sqs.enabled ? 1 : 0
  # ...
}

# Conditional event source mapping
resource "aws_lambda_event_source_mapping" "this" {
  count            = var.sqs.trigger_lambda ? 1 : 0
  # ...
}
```

When integrating services:
- Use optional object variables with defaults
- Create IAM policies conditionally
- Test integration in examples/

### 9. Important Gotchas

1. **Documentation is auto-generated**: Never manually edit between `<!-- BEGIN_TF_DOCS -->` tags
2. **Multi-platform locking required**: Always lock providers for all three platforms
3. **No traditional tests**: Use pre-commit hooks instead
4. **Free-tier defaults**: Don't increase capacity/retention without good reason
5. **Semantic commits required**: PR titles validated by `amannn/action-semantic-pull-request`
6. **CI tests multiple Terraform versions**: Code must work with >= 1.5.0
7. **Module independence**: Each module has its own `versions.tf` with same constraints
8. **CloudWatch retention**: Set to 1 day for free tier (0.5 GB/month free)

### 11. CI/CD Workflows

**Pre-commit Workflow** (`.github/workflows/pre-commit.yml`):
- Triggers on PRs (opened, edited, synchronized, reopened, ready_for_review)
- Runs super-linter, pre-commit with min/max Terraform versions
- Must pass before merge

**Release Workflow** (`.github/workflows/release.yml`):
- Manual trigger only
- Generates CHANGELOG.md and GitHub release
- Commits with `[skip ci]` to avoid loop

**PR Lint Workflow** (`.github/workflows/lint-pr.yml`):
- Validates PR title follows semantic versioning

**Upgrade Dependencies** (`.github/workflows/upgrade-dependencies.yml`):
- Manual trigger
- Runs pre-commit on all files
- Creates PR if changes detected

### 12. Working with Example Code

The `examples/basic/` demonstrates best practices:

**Producer Lambda** (`examples/basic/files/producer.py`):
- Sends messages to SQS
- Uses environment variables for queue URL

**Consumer Lambda** (`examples/basic/files/consumer.py`):
- Triggered by SQS events
- Stores data in DynamoDB
- Publishes to SNS
- Demonstrates error handling

**Template Pattern**:
```hcl
templatefile("${path.module}/files/producer.py", {
  queue_url = module.sqs_queue.url
})
```

Use this pattern to inject resource URLs/ARNs into application code.
